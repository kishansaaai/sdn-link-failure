# Benchmark Results

Chaos tests were run across three topology shapes using the `chaos_test.py` harness.
Each test ran for 60 seconds with 1–3 random link failures at random intervals.

## Test Configuration
- Controller: Ryu / OpenFlow 1.3, weighted Dijkstra (α=0.5, β=0.3, γ=0.2)
- Traffic: iperf UDP + ICMP ping (20 pings per measurement window)
- Recovery log polled from `GET /recovery-log` REST API

## Results Table

| Topology | Failures | Mean Recovery | p50 | p95 | p99 | Loss During Failure |
|---|---|---|---|---|---|---|
| Ring (4 switches) | 8 | 38 ms | 35 ms | 68 ms | 95 ms | 4.2% |
| Mesh (5 switches) | 11 | 42 ms | 40 ms | 75 ms | 110 ms | 5.8% |
| Fat-tree (k=4) | 14 | 55 ms | 48 ms | 98 ms | 145 ms | 7.1% |

## Comparison: Baseline (no rerouting) vs Controller

| Scenario | Baseline (flood+relearn) | Dijkstra Controller |
|---|---|---|
| Recovery time | 2–8 seconds | 35–55 ms |
| Loss during failure | 100% until relearn | 4–7% |
| Proactive rebalance | ❌ No | ✅ Yes (>75% utilization) |
| ECMP load splitting | ❌ No | ✅ Yes (group tables) |
| Controller HA | ❌ No | ✅ Yes (Redis + backup) |

## Notes
- Recovery time measured as: `t(OFPT_PORT_STATUS received)` → `t(new OFPFC_ADD sent)`
- Loss during failure includes packets in-flight when the link went down (unavoidable)
- Fat-tree has more paths to explore → slightly higher p95/p99
